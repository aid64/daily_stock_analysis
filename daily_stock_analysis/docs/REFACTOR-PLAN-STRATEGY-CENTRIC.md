## 二、v4.0 目标架构（方向纠正）

```
┌─────────────────────────────────────────────────────────────┐
│ dsa（主系统）：账户真源 + 决策 + 交互                          │
│  L4 账户真源   PortfolioService（8 表 + append-only 审计）★保留 │
│  L3 执行       order_sheet 状态机 + /买入 + /成交回填 ★保留     │
│  L2 组合层     portfolio_compositor（多策略→目标持仓→调仓单）★新建│
│  L1 策略层     strategies/ 每策略一模块（用户规则同构化）★重构   │
│  L0 交互       飞书指令台（卡片，已改）+ Web 三页 ★保留          │
│  横切 通知     决策事件模型（发送方产事件，渠道消费）★新建       │
│  横切 LLM      解释层（读状态写"为什么"，不决策）★归位          │
└─────────────────────────────────────────────────────────────┘
              ↑ 文件契约（strategy_intake，不打通代码）↓
┌─────────────────────────────────────────────────────────────┐
│ quant（回测裁决所）：策略能不能上，由它说了算                   │
│  BacktestEngine + two_stage（PIT + 真实费率 + 样本外）★保留     │
│  输出：策略回测报告 JSON → dsa 据此把策略 registered→active     │
└─────────────────────────────────────────────────────────────┘
```

**核心决策（全部经实测校正）：**
- **B1. dsa 保留为账户真源**（不做 v3.0 的"降级为投影"——那是基于错误事实）。PortfolioService 强化，不推翻。
- **B2. 策略统一为"目标持仓"语义**：策略层每个模块输出 `StrategyOutput`（目标持仓权重 + 约束满足 + 理由），组合器对比目标 vs 当前账户 → 调仓单。**买入=达成目标，卖出=达成目标，同源** → 天然解决"光卖不买"。
- **B3. 用户规则同构化为策略**（止损/止盈/集中度/E2 各一模块），破位诊断=约束的紧急度标记。
- **B4. quant 只做回测裁决**：策略从 registered→active 的准入，必须有 quant 的回测报告（文件契约 strategy_intake），dsa 不自己判定策略有效性。
- **B5. 通知事件化 + LLM 归位**（已启动：决策包卡片化已完成）。
- **B6. 模块增删**（见第四节总表）。

### P0.9：在线决策层回放基线（批评#1/#5——修正验证纪律覆盖反了）
**问题**：v4.0 把最严纪律给了尚未上线的策略层，却给每天真正输出指令的三层发了免检——结构锚价位（regen 脚本）、破位分档（启发式阈值）、组合器参数（P2 的容忍带/优先级/cadence）。000899 从"立即全卖"翻成"持有观察"就是这一盲区的实证。
**做法**：为这三层建立与"策略"同级的回放/对照纪律（不是等 P3 才管）：
- **决策回放集**：固定一批历史账户快照（含 000899/002475 的历次破位场景），任何改动价位算法/破位阈值/组合器参数后，必须回放这批快照，**输出差异需人工确认（diff 审阅），不得静默变更**
- **参数扰动对照**：破位阈值（2%/5%/1.3/0.7/5日）、容忍带（±5%）、优先级链——每个结构值给出"改成邻近值时决策如何变"的敏感性表，证明不是脆弱拟合
- **变更留痕**：这三层的每次参数/算法变更写入 `docs/decision-layer-changelog`（含变更前后回放 diff）
验收：三层各有回放集+敏感性表；一次价位重生成能产出"哪些标的判决因此改变"的 diff 报告。回滚：回放集是纯读，无副作用。

> **v4.2 修正（发现#2）**：`replay_decision_layer.py` 实际覆盖**两层**——破位分档阈值 + 价位锚（window/buffer 扰动敏感性）；第三层"组合器参数（容忍带/优先级/cadence）"因 P2 未落地而缺席，措辞"三层各有"更正为**"两层已建、组合器层随 P2 补齐并纳入同一回放纪律"**。P2 验收里组合器参数变更须附回放 diff（见 P2）。

### P1.5：首笔执行闭环 + 建议可执行性（v4.2 新增，前置于 P2——发现#4/#5）
**为何必须前置**：实测操作单 09-15~09-23 连续 9 天 `pending`/`fills=0`，真实账本最新成交停在 2026-09-07。P0–P5 全在优化"系统输出的正确性"，无一阶段管"建议是否被执行"。**零执行下，P2 的买侧、P3 的命中率/跟踪误差、P0.9 的回放价值全部无法验证**——等于给没人用的系统做精装修。P1.5 的目标不是写更多代码，是**打通一次真实成交**并**消除让人不愿执行的建议缺陷**。

- **建议可执行性（发现#5，根因之一）**：实测集中度规则对当前 2 股小账户产出"卖出全部 002475 200 股"——总值 ¥13,461，35% 预算 ¥4,711 < 002475 一手 ¥5,495 → 目标 0 股。**对小账户"降集中度"数学上等于"清仓"**，这是不可执行/不合理建议，很可能是零执行的真实成因（不是用户惰性）。修正：
  - 账户规模感知的集中度——当"阈值内可持有量 < 1 手"时，不再机械清仓，改为**保底一手 + 分批降低路径**（或标注"账户过小，集中度无法通过卖出改善，需靠加仓其他标的稀释"），并在依据披露里讲清"为什么这条不是全卖"。
  - 该修正走 P0.9 回放纪律（改集中度目标算法 → 回放 000899/002475 历史快照 → diff 人工确认），因为它改变每日判决。
- **首笔执行闭环（发现#4）**：闭环代码路径（`/操作单`→模拟账本→`/成交回填`→真实账本→`/对比`）已在隔离环境验证可用（direction 护栏、部分成交、sim-vs-real 对比均通过）。P1.5 要拿到**一次真实成交**的落库 + `/对比` 首次产出真实偏差：
  - 降低执行摩擦：决策包已带可复制 `/成交回填` 指令；补一个"首笔引导"——首次无任何 fills 时，决策包/健康提示明确"如何完成第一笔回填"。

#### P2 组合器深化设计（2026-09-19 调研沉淀，来源见附录）
社区/开源（QMT 多策略实战、麦锐再平衡系列、BigQuant 混合策略、optimalportfolios）验证了四个必须内建的机制，补齐原计划的模糊处：

1. **资金冲突消解（多策略选中同一标的 / 总预算只有一份）**——采用**优先级排序**而非简单相加或取平均（社区共识：相加会超配+超预算，平均适合无优先级场景）。dsa 的优先级链已隐含：`止损/止盈（离场）> 集中度（风控）> 现金管理（无风险）> 配置型策略（卫星）`。组合器显式实现这个偏序，预算不足时高优先级先满足。
2. **偏离容忍带（tolerance band）而非机械复位**——每个目标持仓设 `目标 ± 容忍带`（如卫星单票 ±5%），只有偏离出带才触发调仓。**直接复用 order_sheet 现有"差额不足一手不出单"逻辑**，扩展为"差额未超容忍带不出单"。这一条治本地根除"每天微小调仓"和"你又说了又说"的重复指令（再平衡研究实测：季度/带触发比日度频调收益更高、成本更低）。
3. **双频调仓冲突处理**——现金管理（逆回购/打新，日频窗口）与配置型策略（周/月频再平衡）在同一天触发时：**当天只执行一类，再平衡优先，跳过当日择时微调**（BigQuant 实证："同时管会导致下单混乱"）。组合器按策略 `cadence` 字段排他。
4. **操作型 vs 战略型再平衡分离**——操作型=偏离带机械复位（组合器自动）；战略型=目标权重本身调整（E2 分位/股息率vs国债利率等，改的是 mandate.yaml 的目标，需用户或研究裁决，不自动）。**组合器只做操作型，战略型走 strategies.yaml 参数变更**（可审计）。

组合器契约（P2 落地目标）：
```python
def compose(strategy_outputs: list[StrategyOutput],
            account: AccountSnapshot,
            mandate: Mandate) -> RebalanceOrders:
    # 1. 按优先级归并各策略目标持仓 → 合并目标（冲突取高优先级）
    # 2. 应用容忍带：|目标 - 当前| 未出带的标的不进调仓
    # 3. cadence 排他：当日多触发只保留最高频/再平衡
    # 4. position_sizer 预算闸门：总敞口/单票上限/单笔风险
    # 5. 输出 RebalanceOrders → order_sheet 状态机（现有，不变）
```
