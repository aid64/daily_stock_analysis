# 策略目录：从调研到部署的唯一真源

> 编写时间：2026-09-18。来源：知乎/量化社区/学术调研（2026-09-15~17 多轮检索，来源链接见文末）。
> 用途：登记所有候选/在用策略——规则、实证、风险来源、接入点、验证状态。**策略只有在本目录登记后才能进入部署管道**。
> 对实现：`src/services/strategy_engine.py`（运行时评估）+ 仓库根 `strategies.yaml`（参数注册表）。
> 纪律继承：quant 侧预注册纪律（参数取结构值不网格调参、诚实负结果、holdout 隔离）对每一条策略生效。

## 一、状态机与接入管道

每个策略按状态推进，**未达 active 不产生可执行指令**：

```
registered（登记：规则+来源写清）
   → replicating（quant 侧换源复现：真实费率/剔涨跌停ST/只用昨日数据）
   → 对照实验（池子扰动 + 参数扰动 + 样本外切分）
   → shadow（影子跟踪：决策包只展示不落单，接 outcome 统计）
   → active（准入：进决策包信号层）
任意阶段可 → rejected（否决，记录负结果）/ dormant（休眠，策略衰减）
```

**准入裁决自动化（P3，`strategy_intake.py`）**：状态推进不再纯手工改 yaml——
quant 侧把回测裁决报告 JSON（schema=`strategy_intake_verdict_v1`，含
`data_as_of/verdict/metrics/oos_window`）写到 `quant_research/output/strategy_intake/`，
每日管线 `process_intake_dir` 消费并按规则推进：

- `verdict=promote` → 先过**数据新鲜度门**（`data_as_of` 滞后 > 阈值交易日
  则拒绝并告警，不静默用过期数据裁决），再推进一档（registered→shadow→active，
  不允许跳级）；
- `verdict=reject` → rejected；`verdict=hold` → 保持现状；
- schema_version 不匹配 / 缺字段 → fail-closed 拒绝。

**运行态暂停与注册表打通**：`strategy_autostop` 触发暂停时把注册表对应策略
状态同步为 `dormant`（此前 autostop 用独立表、与注册表脱节）。跑输判定加
**幅度门**（`STRATEGY_AUTOSTOP_UNDERPERFORM_MARGIN_PCT`，默认 1%）——一期
跑输基准需超过该百分点才计入连续跑输，避免跑输 0.01% 也累计触发降级。

> **命中率口径诚实性（P3 批评#14）**：outcome 统计的 `hit_rate_pct` 是**绝对
> 方向命中率**（带 `hit_rate_is_absolute` 标记），不是相对基准的策略 alpha；
> 策略真实能力须结合影子跟踪误差（`shadow_metrics_service`）判读。买入执行率
> 在用户零执行期是虚荣指标，不作为策略能力度量。

两类策略免回测直接 active（规则性正期望/无风险利率，不属于"预测市场"）：
- **国债逆回购**：无风险利率，不存在"验证收益"问题
- **转债打新**：2026 年 45 只新债 32 只顶格 57.3%、首日均涨 52.95%（`bond_new_issue_calendar.py` 文档化数据）；信用申购零成本，下行被债底封住

## 三、现金管理层（active）

### 3.1 国债逆回购窗口（reverse_repo_window）

- **规则**：月末/季末/节假日前（次日休市或本月最后交易日）操作 1 天期 GC001（沪 204001）/R-001（深 131810），1000 元起、1000 的整数倍，券商 App"卖出"方向下单。
- **实证**：日常年化 1.4-1.8%，窗口期 2%+；节前 1 天期可赚 N 天利息（春节一次 11 天）。证券时报/证券日报 2026 年多次发文确认。
- **风险来源**：仅机会成本；注意尾盘利率跳水、避免节后第一天操作计息陷阱。
- **接入**：`strategy_engine.reverse_repo_window`——决策包现金块直接给操作建议（品种/金额=可用现金取整）。

### 3.2 转债打新（cb_new_issue）

- **规则**：信用申购零成本顶格申购；中签 T+2 16:00 前缴款（弃购 3 次禁打半年）；上市首日 14:50 前卖出落袋。
- **实证**：见 `bond_new_issue_calendar.py` 头注释（2026 年 45 只、32 只顶格、单账户年期望 600-2000 元）。
- **接入**：`BondNewIssueCalendarService` 已作为后台任务三段式推送（申购/缴款/上市）；决策包内由 `strategy_engine.cb_new_issue` 汇总近 2 日提醒（不重复推送，只做盘前汇总）。

## 四、低风险层（registered，待复现）

### 4.1 转债高 YTM 底仓

- **规则**：到期收益率 2%+、评级 AA（及）以上、价格贴近面值，持有到期吃 YTM+期权价值。
- **依据**：本项目 quant 侧研究结论——`ytm_true` 因子全样本稳定正 IC（含 2021 双低死亡年 +0.067），AA/A- 段最强；E1 合成因子 fail 不影响单一期限维度。
- **风险来源**：发行人信用事件（评级过滤控制）、低价债流动性。
- **接入**：PIT 数据和评级过滤全在 quant 侧，复现成本低；入选后进决策包"现金配置"块。

### 4.2 封基/定开 LOF 折价套利

- **规则**：折价率 >5% 才出手（折价即安全垫），持有至开放/到期收敛。
- **实证**：2026 年典型标的折价已收敛至 ~3%，空间薄，**挂监控等窗口**。
- **风险来源**：封闭期内净值下跌吃掉折价；当前监管重塑后 LOF 溢价被制度性挤出。
- **接入**：扩展现有 `etf_premium` 监控的折价扫描；窗口打开才进决策包。

### 4.3 红利低波持有（不做择时）

- **规则**：核心仓配置中证红利低波类资产，**持有型**，禁止叠加择时信号。
- **实证**：全收益 2018-2026 +68.6%（股息贡献 49pct）；2026 年 7-9 月 +10% vs 创业板 -23%。
- **两条教训（知乎实证）**：① 回测必须用**全收益指数**（价格指数只含 ~20% 收益）；② 8 年 75% 胜率的 MA20/MA250 择时信号 2025-10 起连续 17 周失效——择时型会翻车，持有型成立。
- **风险来源**：权益市场整体下跌（2022 年 -20% 级），不是存款替代。

## 七、运行时策略共存契约（2026-09-27 核实）

部署中的"策略"分布在三套命名空间，职责不同——同名不同物是最大误解源：

| 命名空间 | 角色 | 真源 / 消费方 |
| --- | --- | --- |
| 仓库根 `strategies.yaml` | 策略**身份与状态**注册表（registered/shadow/active/dormant/rejected） | 状态推进：`strategy_intake`（裁决报告）+ `strategy_autostop`（运行态暂停回写） |
| `src/services/strategies/` | **运行时决策模块**（user_rules/concentration/e2_timing/breach + types/adapters） | 生效编排：`portfolio_compositor.compose_account_decision` |
| `daily_stock_analysis/strategies/*.yaml`（14 个） | 旧 agent 技能策略（K 线形态类），属 LLM 分析层 | `src/agent/skills/` 消费，不进账户决策 |

**唯一裁决顺序**（定义于 `strategies/types.py` TIER_PRIORITY）：
`exit_rule(10) > risk_control(20) > cash_management(30) > low_risk(35) > satellite(40)`

**当前生效路径**（实盘行为 = 下列顺序，逐票提前 return 保证互斥）：
1. `user_rules.decide_position`——止损/止盈/破位分档；止损触发即返回，该票不再进集中度分支；
2. `concentration.apply_concentration_targets`——只修正 REDUCE 腿（不碰 SELL/HOLD；**当前 R2 已被用户停用**，不参与判决）；
3. `e2_timing`——只决定现金会话语义，不产持仓腿；
4. `strategy_engine`——逆回购/打新现金信号进动作区，**只展示不落单、不可回填**（U1 边界）。

**U0 签署实况（2026-09-26 台账，source: user_delegated_20260926）**：5 条规则全部签署——R1/R3/R4/R5 confirmed；**R2（集中度）disabled**，理由"单向阀问题：无可买标的时机械卖出换死现金；待买侧授权或找到可买标的后启用"。当前生效纪律 = R1 + R4 + R5（+R3 惰性）。

**U6 进度（2026-09-27）**：①`/买入` 已纳入同一风险制度——回复新增风险提示行（成交后单票占比对照 mandate 25% 参考上限 + E2 防守区状态），不阻断（用户是执行引擎），提示失败静默跳过；②黄金等价测试已扩到四场景（全卖/WAIT/减半/REDUCE）**全部等价**——compose 接线在已测场景内行为保持，"接线或弃用"的裁决依据齐备（接线时点仍 = 买侧首条自动买入腿之前）。

**已知语义（知情项，非 bug）**：
- 止损破位 WAIT（暂缓一日）→ 该票当日不产生任何腿（含集中度减仓）——离场优先级覆盖风控；
- 集中度"减仓=清仓"已由 P1.5 修正为保底一手/持有提示（账户规模感知）；
- E2 防守区当前只影响文案与（未接线的）预算闸门，不阻断 `/买入`。

**已建·未接线清单（接线条件见 v5.0 计划 U6）**：

| 组件 | 状态 | 风险 / 后果 |
| --- | --- | --- |
| `compose()` 归并 / `adapters` / `evaluate_strategy_outputs` | 已建+测试（1 个黄金等价场景），**未接入运行时** | 两套归并器并存；接线前须扩等价测试（WAIT/REDUCE/减半场景） |
| `apply_budget_gate`（mandate 25%/95% 预算帽） | 已建+测试；只约束组合器买入腿（当前无） | 手工 `/买入` 不受单票/敞口预算约束——两套风险制度 |
| `strategy_autostop` | service/API/dormant 回写齐备；**无管线调用点、无运行数据源** | 策略劣化不会自动暂停（仅手动/API 触发） |
| `strategy_intake` 裁决报告 | 消费端+生产端齐备（`build_intake_verdict.py`；promotion_cap 已机器强制）；`output/strategy_intake/` 当前无报告 | etf_momentum 停在 registered；报告产出即自动过状态机（新鲜度门+上限门） |

**买卖单向阀（R2 停用根因，"光卖不买"的残留形态）**：卖出规则（R1）与买入路径（观察池//买入）之间没有合成器——R2 集中度在无买入标的时会机械卖出换死现金，故被停用。收口条件 = U6。
