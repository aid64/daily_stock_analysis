# 安全契约与研究证据复核：优化修改方案

日期：2026-09-12。范围：DSA 与 quant_research。性质：只读调查与待实施方案；本轮未修改业务代码、配置、账本，未下单或发送测试通知。

## 1. 决策结论

目标仍是低频个人投资助手：覆盖真实持仓，明确今天做什么或为什么不做，人工执行，可靠对账，减少注意力负担。当前不应宣布进入可执行影子期。已有组件可以保留，但暂停、现金、回填、快照和研究绩效存在可直接复现的契约缺陷。

本文纠正此前计划的证据错误；不改写既有实验结果，不把旧模拟成交删除后伪装成干净业绩。所有整改结果必须有反例测试和验收记录。

## 2. 已确认的问题与证据

### A. 暂停与负现金会意外生成卖单（P0）

`daily_stock_analysis/bot/commands/order_sheet.py:218,235` 将目标置空；`src/services/order_sheet_service.py:134,163` 将缺席目标解释为零仓位。已有转债持仓、有有效价格且达到申报单位时，会生成卖单。附加暂停文案不会消除该指令。没有持仓的测试无法覆盖这个反例。

旧 pending 路径（order_sheet.py:145）也只加提示后展示原 orders。暂停状态文件损坏或读取失败时 trading_halt_service.py:27 返回未暂停。这意味着已宣称的 kill switch 并未可靠落实。

### B. 回填会造成两个账本不一致（P0）

`bot/commands/fill.py:87` 先保存单据成交状态，再在 99 行写真实交易。真实账本写失败，文件已标成交；没有跨存储事务。入口没有传入底层已支持的 trade_uid/dedup_hash。

`order_sheet_service.py:282` 以 symbol 覆盖 fills，全部 symbol 出现即 filled，不按累计量判断。计划100张回填10张即可完成单腿；后续回填覆盖单据数量，却在真实账本继续累加。不能用订单ID作为唯一成交ID，因为一张订单可以有多次合法部分成交。

### C. 快照并非可靠事实源（P0）

`decision_snapshot_service.py:134` 对 OrderLine 调用不存在的 to_dict；订单非空即丢失 order_sheet 块。缺信号被 evaluate_plan_freshness 视为 fresh；PIT错误仅进入 pit_error、不进入质量告警。fresh=true 不能代表可执行。

快照仍在事后读取多份可变文件；同一 snapshot 未确保数据/持仓/单据同版本。每日归档覆盖不能回答“当天不同时间发过哪些版本”。固定tmp路径还需要并发验证。

### D. 入金恢复路径指向错误命令（P0）

`bot/commands/portfolio.py:75` 的 /持仓登记只支持买卖交易，不支持入金。后端已有现金事件 API（api/v1/endpoints/portfolio.py:264）和 record_cash_ledger，不应新增第二本现金账。

负现金仅证明记录存在差额，不能未经核对断言用户没入金，更不能自动补12390元。零现金也可能是正常满仓。

### E. “已发送”状态可能是假成功（P0）

notification_digest_service.py:298 忽略发送结果就写 digest_sent；daily_pipeline_service.py:143 同样未据发送成功判断日任务成功。无渠道或全部失败可能正常返回失败对象，并不抛异常。已入队、已送达平台、用户已读、真实成交必须分开。

JSONL总线读-改-写缺少并发事务保护。一次替换可能覆盖另一个线程刚写入的通知。60%相邻日阈值只能发现骤降，不能保证完整：283→56→56 的最后两日会互相通过。

### F. 对账和模拟统计不可靠（P0/P1）

simulation_ledger.py:122 生成单据即假设全量成交；不是行情驱动撮合。compare_with_real:152只取真实交易前100条，以日期/代码/方向匹配第一笔，可能把一笔成交重复匹配多张单。无匹配不能区分用户放弃、未收到、未回填、确实未成交。

此前发现的28条模拟记录包含与测试fixture一致的数量和价格以及不存在的sheet_id；污染高度可疑，但不能仅因标的今天退市就删除历史交易。匹配率0%不能用来评判用户执行率。

## 3. 必须撤回或降级的研究结论

1. **负IC不等于双低失效。** 原始双低值越低越好，原始因子与未来收益负相关正是预期方向。2025后接近零值得研究，但不足以证明拥挤这一因果。
2. **9月缺数不能解释1月空调仓。** 各季首日需独立重建数据覆盖和每层过滤计数。top_n=5 返回5条不能拿去比较 min_candidates=15 判定完整候选池大小。
3. **无调仓不等于持现金。** two_stage.py:101只写非空目标、next:255缺席时沿用持仓；run_paper_tracking.py:139却将无计划季度输出平盘现金。独立现金起始实验可以这样定义，但不能串成连续持仓业绩。
4. **E1结论不可直接用于选策略。** e1_composite_backtest.py:54把整个窗口最后一条溢价率映射到历史日期；YTM约每5日采样，194行却按每年4期年化。还存在取整余款丢失、强制一手、固定扣费与报告费用不同口径。先修评估器，不能宣布因子已被严格证伪。
5. **E2只能列为待复核假说。** e2_valuation_timing.py:47用截面价格中位数变化代理可投资组合；161行截到2026-08-08，204行current_state来自历史窗口末值。95.1%不能称“今天分位”，31%回撤改善不能直接当作真实组合证据。
6. **交易成本已有分析，但模型尚不统一。** 滑点产物自述期末解析扣减、不重算回撤/夏普；最低佣金不是所有品种统一适用的监管事实，必须以账户和品种费用表核验。
7. **已有资产不要重复建设。** 依赖锁文件、holdout模块、三表生成代码都已存在；应查使用覆盖和结果有效性，而非沿用“完全没有”的旧文档。

上述代码证据是对实现的审查，不等于证明账户已经发生对应亏损。

## 4. 外部一手资料及采用边界

- SQLite事务保证：https://www.sqlite.org/transactional.html 。同一数据库事务全成或全败；不覆盖外部JSON文件。采用其事务边界组织真实成交、订单投影和通知待办。
- Alpaca订单文档：https://docs.alpaca.markets/docs/trading/orders/ 。订单有客户端标识、部分成交、撤销待确认、已撤销、过期等状态。仅作为软件设计参考，不套用其美国市场交易规则。
- Backtrader成交说明：https://www.backtrader.com/docu/order-creation-execution/order-creation-execution/ 。新订单不能按已经观察到的当前bar认定成交；限价单须匹配后续价格。采用为影子撮合的最低时序约束。
- Fowler熔断器：https://martinfowler.com/bliki/CircuitBreaker.html 。基础设施调用熔断可半开探测；人工交易暂停和自动风险停止应独立，不能因接口恢复自动恢复交易权限。
- Tushare行情文档：https://tushare.pro/document/2?doc_id=187 。之前取得文档和账户接口证据支持日行情及字段可得性；数据供应商不是交易所，字段不能代替法律规则原文。

本轮SQLite WAL页面超时；此前交易所具体规则页访问失败，仍属未核验项。不得再写“本地规则表与交易所制度已确认一致”。API返回成功也不证明中转模型身份与直连模型完全相同。

## 5. 最终架构取舍

保留两个项目边界，避免微服务化：

- quant：数据采集、PIT发布、研究与版本化候选提案；
- DSA：账户账本、风险裁决、订单意向、人工执行回填、通知；
- 飞书：主要操作入口；Web/Desktop：同源状态、审计与导入界面；
- LLM：解释事实、标识不确定性，不更改价格、数量、账户、风险状态；
- SQLite：复用真实账户数据库存业务事件/订单/通知outbox；
- Parquet：研究行情；跨项目提案使用版本化文件及manifest；JSON快照是不可变发布物或可重建读模型，不是另一套账户账本。

推荐流程：完整数据发布 → 候选提案 → 账户与风险裁决 → 冻结决策版本 → 单据与通知outbox提交 → 平台发送回执 → 人工下单 → 成交事件事务入账 → 重建账户/订单/对账投影。

## 6. 修改批次与验收

### R0：先修危险控制语义（预计3—5工作日）

- 统一 gate 返回 allow、observe_only、blocked、reduce_only 与原因码；目标为空只表达策略语义，绝不作为暂停实现。
- 暂停检查放在缓存返回、生成及发送指令之前。暂停时不显示旧单为可执行；保留历史供查询。
- 暂停状态不可读时阻止新指令并报告unknown。恢复操作只解除人工暂停，不能解除现金/数据/风控阻断。
- 负现金保留真实数值并禁增风险；若允许减仓，仅保留策略原本的减仓，不额外生成清仓。
- 发送结果严格检查真实渠道回执，失败可重试；同日任务分数据完成/决策阻断/通知待发/已发。
- 修快照非空订单序列化、缺信号误绿、PIT错误误绿。fresh、complete、reconciled、executable分字段。

验收反例：持有10张且暂停时0买0卖；已有pending买单也不可执行；现金负但目标仍为持有时不得清仓；状态文件损坏不得放行；通知返回all_failed时不得标成功；有非空orders的快照完整保留单据。测试全部使用临时库/目录并阻止真实发送。

### R1：账户与成交事务（预计1—2周，依赖R0）

- 复用record_cash_ledger增加明确入金/出金入口，保留来源和日期，不凭负数自动补账。
- 引入account_id/order_id/fill_id/message_id，区别消息重放与两笔相同价格数量的合法成交。
- 同一数据库事务内提交成交、现金/持仓变化、订单累计成交投影及outbox；JSON从数据库生成。
- 支持部分成交累计、剩余量、取消待确认、过期、计划外/迟到成交。过期不拒绝登记真实历史成交，而是记录成交时间和关联异常。
- 超计划量或价格偏差进入复核；保留真实成交事实，不强行按计划改写。

验收：同一fill重试只入账一次；两笔不同fill同价同量均记录；100张订单分30/70累计正确；任一步数据库失败不出现半更新；撤单请求不冒充已撤单；晚到回填可审计。

### R2：数据发布与生命周期（预计1—2周，可与R1部分并行）

- 优先按交易日批量取Tushare cb_daily，结合条款/生命周期构造当日有效证券集合；AkShare作核验或降级，不再每天盲扫全部历史退市目录。
- complete/partial/failed manifest包含预期集合、实际集合、缺失明细、日期、单位、来源、hash。候选判断只消费已发布完整版本。
- 连续缺数不能相互认证；60%阈值只能作为异常启发式。关键持仓缺价独立阻断，不能被全市场比例掩盖。
- 生命周期缺失或过期不静默放行；按公告可知时间和生效时间双时间建模，区分提示、不赎回、实施、到期、退市。
- 移除危险的默认重归一：阻断一只后不能自动把余下20%提高到25%，除非风险预算允许；默认剩余留现金。
- 工作日/节假日/盘前截止由交易日历决定，不用固定7个自然日代表可交易新鲜度。

验收：完整283、后续56、再56时后两日都不发布；历史日不能看到未来公告；1月与9月覆盖单独统计；阻断后风险敞口不增加；数据拉取失败仍可查询上次版本但不冒充今日可执行。

### R3：影子账本与研究重验（预计2—4周，依赖R1/R2）

- 隔离疑似测试记录，保留备份、来源、判据和迁移清单；不能按“今天已退市”删除历史记录。
- 区分计划、假设成交、行情撮合成交、真实成交、重放实验。无主记录标unknown，不算用户未执行。
- 将现金季度标注为独立重放，不拼接连续账户；连续模拟继承持仓/现金并处理赎回结算。
- 修E1时点对齐、频率年化、现金守恒、费用；E2用可投资持仓收益核验，current_state带as_of。统一回测成本、现金、停牌及交易规则。
- 旧结论标superseded/invalidated，修实现不调参；历史结果全量重验，holdout不参与选择。若已看过测试期结果，登记污染并启用新的前瞻验证区间。

验收：日期真实跨度年化；总资产守恒；入选信息时间不晚于决策时间；假设限价未触及时不能成交；模拟与真实按order/fill匹配且支持分页、买卖方向滑点和数量加权。

### R4：组合决策产品（预计2周，依赖R0—R3关键闸门）

- 股票、转债、现金统一风险预算，研究信号与可执行信号分开。1万元只是初始背景，以用户确认的账户权益/现金为准。
- 实际持仓立即获得数据质量、集中度与分析覆盖，不必等待策略盈利才支持002475；没有阈值不等于没有分析，没出消息也不等于已分析。
- 每笔展示预计往返成本与盈亏平衡涨幅，不捏造预期收益。成本、风险阈值先作为待确认政策值，不能包装成实证最优参数。
- 每日一份决策包：结论、来源日期、账户状态、最多必要订单、阻断原因、未完成回填、实际模型来源。普通市场信息合并；重要风险即时。
- 扫描漏斗：确定性批量数据过滤→少量候选→解释；不对全市场逐只调用LLM。

验收：消息和Web引用同一decision_id；模型切换不改交易事实；LLM故障仍能出确定性风险报告；每个持仓显示success/failed/not_run与日期。

## 7. 时间与退出条件

先完成R0再开始运维观察；8—12周可以检验可靠性和使用负担，不能证明季频策略alpha（通常只有少量调仓事件）。策略验证至少跨多个独立调仓周期和市场情景，时间再长也不自动视为通过。

运维门槛：暂停反例0逃逸、重复成交0入账、故障注入无半事务、过期/缺数据0可执行单、未送达0假成功。策略门槛另行预注册，包括账户真实费用、压力滑点、可投资基准、净收益与回撤，不复用未核验E1/E2指标作准入。

用户合理放弃订单不算失败；只有已审批且可执行的订单进入执行率分母。账户异常、未解释成交或版本错配时只读观察；没有净优势时保留工作台，不强推实盘。
