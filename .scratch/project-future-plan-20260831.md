## 1. 当前判断

### 1.1 DSA 主项目

DSA 已具备完整的“数据→分析→报告→通知→Web/桌面”产品闭环，近期新增的事件套利、转债打新、配债登记、ETF 溢价率监控，将它从单纯的 AI 分析工具扩展为可执行的个人投资工作台。

当前最重要的问题不是继续增加页面或通知渠道，而是：

1. **测试与全局状态隔离仍有长尾风险**：已将全量离线失败从 57-81 个随机失败压到 0-3 个；环境污染、Windows 临时文件句柄、CLI 乱码、平台不兼容测试已分别处理。残余是 `IntelligenceService.fetch_enabled_sources` 的长负载偶发 `saved_count=0`，应作为独立可靠性问题收口。
2. **运行路径曾不一致**：CLI schedule 已注册市场监控，serve/Web runtime scheduler 原本没有；已补齐默认装配。后续要有“CLI schedule 与 serve/Web schedule 的任务清单等价”测试，防止以后再漂移。
3. **JSON 文件状态已是临界点**：三个市场监控目前各自用 JSON 文件去重。对单机可用，但未来加 Web 配置、手动确认、历史复盘、多个运行实例后，需要统一事件状态/投研日志模型。
4. **本地分支积累需治理**：本地 HEAD 比 `origin/main` 多 39 个提交；网络/代理阻断导致无法拉取上游，不应直接推送或强行 rebase。需要先形成可审计的变更分组和上游冲突审计。

### 1.2 quant_research

quant_research 已完成从“脚本式回测”到“研究基础设施”的跃迁：

- 但策略级实盘门槛仍未通过：ETF 动量与 MWU+转债的 WF 样本外结果不稳定；P1-1 静态温度计门控使 OOS 从 +1.94% 恶化至 -13.66%，已按预注册规则拒绝采纳。

因此，下一阶段不能再围绕“找一组漂亮参数”工作，而应围绕“如何把显著的因子毛 alpha 在真实成本、容量、regime 下转成可部署的净 alpha”工作。

## 2. 北极星与硬门槛

### DSA 北极星

形成一个每周可重复执行的个人投资运营闭环：

```text
发现机会 -> 结构化核查 -> 人工确认 -> 记录仓位/事件 -> 结果复盘 -> 更新规则
```

监控只负责发现与提示；不自动下单，不将公告关键词、价差、AI 输出误称为确定收益。

### quant_research 北极星

不是“回测更好看”，而是找到至少一条满足以下条件的策略，再考虑 paper/live：

1. 数据冻结后才研究，研究期与最终 OOS 期分离。
2. 所有尝试纳入实验注册，真实试验次数 N 可追溯。
3. 成本 1x/2x/4x 敏感性下都不被费用完全吞噬。
4. OOS 净收益为正，且折间一致性达到预先声明的标准。
5. 执行约束（最小手数、T+1/T+0、涨跌停、停牌/退市/强赎）已在回测和 paper 路径同构。

在满足以上条件前，`LiveMWU`、TDXJK、未来 QMT 适配都只用于 read-only/paper 验证，不向真实账户发订单。

### 阶段 1：DSA 可靠性收口（优先级 P0）

#### 1.1 IntelligenceService fail-open 长尾

现象：`test_fetch_enabled_sources_is_fail_open` 单独及小组合通过，在 20-30 分钟全量负载下偶发 `saved_count=0`，两个源均被归为 upstream failure。

计划：

1. 在 `IntelligenceService.fetch_source` 中保留原始失败阶段（DNS / request / feed parse / upsert）到结构化诊断对象，不仅保留统一 `upstream request failed` 文案。
2. 为测试使用纯本地 feed parser 或注入式 response reader，避免将“批处理 fail-open”测试耦合到全局 `requests`/DNS/SQLite 时序。
3. 将 `upsert_items` 与 `apply_retention` 分别测量与记录；若 SQLite 短暂锁冲突，使用已有 DB 写入重试策略而非把成功 feed 降级为 upstream failure。
4. 增加全量压力回归：重复运行该测试组至少 10 次，确认无失败。

**验收**：全量离线测试 0 failed；fail-open 测试在请求失败时仍保留好源的 saved_count；诊断不泄漏 token/URL secret。

#### 1.2 测试治理

1. 将 `tests/conftest.py` 的环境隔离提炼为正式测试基础设施，不依赖隐式全局状态。
2. 清理仍在模块 import 阶段写 `ENV_FILE` 或写入真实仓库路径的测试，统一使用 fixture。
3. 将 native Windows、WSL、POSIX-only 测试明确分层和 marker，避免“测试失败”掩盖“产品平台不支持”。
4. CI 增加两条命令：
   - `pytest -m "not network"`。
   - 受污染高风险组重复运行（例如 3 次）以发现时序回归。

### 阶段 2：DSA 投资工作台收敛（优先级 P1）

#### 2.1 统一市场事件模型

将事件套利、转债打新、配债、ETF 溢价从三个 JSON 去重文件逐步迁移到统一事件日志：

```text
InvestmentEvent
- id / source / event_type / symbol / observed_at / effective_at
- payload（公告 URL、要约价、现价、IOPV、配售比例等）
- decision_state（new / reviewed / ignored / tracked / closed）
- dedup_key / notification_state / outcome
```

先保持 JSON/SQLite 二选一的轻量实现；不引入远端消息队列或多服务架构。

收益：Web/桌面可展示“发现→人工确认→结果”的完整链路，后续能反哺规则与研究。

#### 2.2 事件套利从“关键词提示”升级为“结构化核查卡”

1. 增加公告正文提取接口（不靠标题正则猜全部要约条款）。
2. 结构化字段：要约类型（全面/部分/换股/现金选择权）、要约价、要约比例、申报期、前置审批、风险状态、现价/名义价差。
3. 价差卡片区分：`可计算`、`缺关键字段`、`市价高于要约价（投机盘）`。
4. 增加人工确认按钮/备注，不自动推荐仓位。

#### 2.3 数据源双重验证

为事件套利和 511380 溢价率补第二信息源：

- 事件：集思录套利数据页/公告原文解析与东财公告流交叉验证。
- ETF：集思录 IOPV/基金公司数据与东财 IOPV 交叉验证。

先做适配器与 source provenance，不承诺任一免费源永远可用。

### 阶段 3：quant_research 研究重开（优先级 P1）

#### 3.1 成本是第一研究变量

双低 IC 显著但两段式基线换手 52x，说明下一轮研究优先目标不是加因子，而是降低交易成本。

新假设必须独立预注册，建议第一条是：

```text
假设 H1：rank-buffer + 最小换手约束能在不显著损害因子暴露的前提下，
把月频转债双低策略的年化换手降低至少 30%，并在成本 2x 下维持不劣于
当前两段式基线的 OOS 净收益。
```

实现方案：

1. 持仓缓冲：当前持仓只有跌出 `top_n + buffer` 才换出。
2. 最小交易阈值：目标权重差额小于一手/最小金额则不交易。
3. 换手惩罚目标：候选分数减去预估交易成本与换手惩罚，不做纯分数排序。
4. 训练期只选择 buffer/惩罚的有限、预注册候选；最终 OOS 期不再触碰。

#### 3.2 扩展因子必须先过单因子诊断

目前证据表明：双低显著，单独溢价率不显著。下一批因子按以下顺序：

1. 发行规模（当前 `issue_size` 静态近似，必须标明不是历史剩余规模）。
2. 信用风险/评级迁移，先解决历史时点语义再进模型。
3. 强赎距离、回售距离、下修事件状态：先采集/构造真实 PIT 字段，不能用今天条款回填历史。
4. 每个因子先出 IC/RankIC、覆盖率、稳定性、成本影响报告；不通过再组合。

#### 3.3 新 OOS 设计

现有 2020-2026 已被多轮研究触碰，不能继续把它称作最终 OOS。

1. 冻结当前所有产物和实验注册。
2. 新增 2026-08-09 之后的数据仅作为最终 holdout，直到 H1 的规则/参数冻结后才看收益。
3. 如果样本太短，先做 paper tracking，不将短窗口年化为策略能力。
4. 每月输出“预测 vs 实现、成交 vs 计划、成本 vs 模型”三表。

### 阶段 4：执行通道与账户安全（优先级 P2）

1. QMT/miniQMT 只做 read-only PoC：读取账户、持仓、行情、订单回报；不下单。
2. 新增 `BrokerGateway` 进程边界：信号进程与交易进程隔离；交易进程默认 `BUY_ENABLED=false`。
3. 每次执行前：持仓对账、当日重复委托检查、T+1/T+0 可卖数量检查、涨跌停可成交检查。
4. 每次执行后：JSONL/WAL 记录、订单状态轮询、未成交撤单策略、人工告警。
5. 在策略过研究门槛前，PaperBroker 持续运行一个完整年报季/强赎周期。

### 阶段 5：外部调研恢复后（优先级 P1）

网络/额度恢复后执行以下调研，不用登录即可完成；需要登录的平台（聚宽、集思录高级页、QMT 券商文档）再向用户询问：

1. 上游 DSA 的 PR #2214 之后变更审计：数据源、runtime scheduler、config、monitor、local_cli、测试基础设施冲突矩阵。
2. 2026-08/09 转债市场状态：存量、强赎、新券供给、双低中位数，决定 H1 的研究窗口。
3. QMT/miniQMT 最新开户与 xtquant 稳定性、程序化交易/佣金监管变化。
4. backtrader/vectorbt/qlib/rqalpha/vn.py 近期架构变化：仅借鉴，不迁框架。
5. 集思录/雪球/聚宽的一手实盘帖：只采集可审计规则与风险教训，不把自报收益当证据。

1. 不为“追上上游”盲目 rebase 或 push 本地 39 个提交。
